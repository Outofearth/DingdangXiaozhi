# 构建与适配

从零把 APK 编出来，以及在别的设备上跑起来要改什么。

---

## 1. 环境要求

| 组件 | 版本 | 用途 |
|---|---|---|
| JDK | 8+（含 `javac`、`keytool`） | 编译 Java、生成签名密钥 |
| Python | 3.6+ | 构建脚本里的注入与打包步骤 |
| Android SDK Build-Tools | 30.x 或 android-11 目录版本 | `aapt2` / `d8` / `zipalign` / `apksigner` |
| Android Platform | **API 27**（`android-8.1.0`） | `android.jar` |
| NDK | r21e 或更高 | 只在重编 `libopus` 时需要 |

系统：Windows + Git Bash 实测可用；Linux / macOS 需把脚本里的 `.exe` 后缀去掉（见第 6 节）。

---

## 2. 准备工具链

构建脚本不下载任何东西，全部离线。按这个结构放好：

```
<SDK 目录>/
├── build-tools/android-11/        # aapt2.exe / aapt.exe / zipalign.exe / lib/{d8.jar,apksigner.jar}
├── platforms/android-8.1.0/       # android.jar
├── maven-jars/                    # 见下表，5 个 jar
└── ndk/<版本>/                     # 仅重编 .so 时需要
```

`maven-jars/` 里的 5 个依赖（从 [Maven Central](https://search.maven.org/) 直接下）：

| 文件 | 用途 |
|---|---|
| `okhttp-3.12.13.jar` | WebSocket 与 HTTP |
| `okio-1.17.5.jar` | okhttp 的 IO 依赖 |
| `jcifs-2.1.28.jar` | SMB 客户端（jcifs-ng） |
| `slf4j-api-1.7.36.jar` | jcifs 的日志门面 |
| `slf4j-nop-1.7.36.jar` | 把 jcifs 的日志丢掉 |
| `bcprov-jdk15on-1.70.jar` | SMB 需要的加密算法 |

版本号不必完全一致，但 okhttp 3.x 与 okio 1.x 要配套（3.12 配 1.17）；
换成 okhttp 4.x 需要 Kotlin 运行时，本项目没接，不兼容。

## 3. 构建

```bash
cd xiaozhi-client
export ANDROID_SDK=/path/to/your/android-sdk     # 或放在 ../build_env/android-sdk

bash build.sh speaker      # 横屏音箱版
bash build.sh mobile       # 自适应手机/平板版
```

脚本会依次做：

```
[1/5] aapt2 compile      资源编译成 .flat
[2/5] aapt2 link         资源 + 清单 → 基础 APK，生成 R.java
[3/5] javac              编译全部 .java（--release 8）
[4/5] d8                 转 DEX（含 5 个依赖 jar）
[5/5] 打包 / 对齐 / 签名   加入 .so，zipalign -p 4，apksigner 签名
```

产出 `xiaozhi-client/xiaozhi-speaker.apk`，约 2.7 MB。

**两个目标只差一件事**：`AppConfig.IS_SPEAKER` 与清单里的 `screenOrientation`。
脚本会生成 `AppConfig.java` 并复制清单到 `build/`（原清单不动），所以：
**不要手改 `AppConfig.java`**，它每次构建都会被覆盖。

**签名**：`debug.keystore` 不存在时脚本自动用 `keytool` 生成（口令 `android`）。
它只用于本地安装调试，不要用于分发。真要发布请换自己的密钥：

```bash
keytool -genkeypair -keystore my-release.jks -alias mykey \
        -keyalg RSA -keysize 2048 -validity 10000
apksigner sign --ks my-release.jks --ks-key-alias mykey \
        --out xiaozhi-release.apk build/aligned.apk
```

## 4. 重编 libopus（可选）

仓库已经带了编好的 `prebuilt/{armeabi-v7a,arm64-v8a}/libopusjni.so`，**正常构建不需要重编**。
只有改了 `src/jni/opus_jni.c` 或想换 opus 版本时才需要：

```bash
# 1) 下载 opus 源码（BSD 许可）解压到工程根目录
curl -LO https://archive.mozilla.org/pub/opus/opus-1.3.1.tar.gz
tar xf opus-1.3.1.tar.gz -C xiaozhi-client/

# 2) 编译（先编 v7a，再编 arm64）
cd xiaozhi-client
bash compile_native.sh arm
bash compile_native.sh arm64
```

脚本直接用 NDK 里的 LLVM 交叉编译器，不跑 `configure`（Windows 下 configure 交叉编译极慢），
配置头用工程自带的 `opus_config/{config.h,version.h}`。

## 5. 移植到别的设备

按改动量排序，从最容易的往上：

### 5.1 屏幕与方向

- 布局：`src/res/layout/` 下 9 个文件，以 `LinearLayout` / `RelativeLayout` 为主，没有 ConstraintLayout
- 横屏锁定：`AndroidManifest.xml` 里 `android:screenOrientation="landscape"`
  （`mobile` 目标构建时脚本会改成 `unspecified`）
- 视频页：`VideoActivity` 用 `SurfaceView`，比例按 `AspectRatio` 自适应
- 字号：`res/values/styles.xml` 与设置页的「外观」分组

### 5.2 音频

| 参数 | 位置 | 本机取值 |
|---|---|---|
| 录音采样率 / 声道 | `AudioCapture` | 16000 Hz / 单声道 / PCM16 |
| 帧长 | `AudioCapture.FRAME_MS` | 60 ms |
| 播放采样率 | `AudioPlayer` | 24000 Hz |
| AudioTrack 缓冲 | `AudioPlayer` 构造处 | 按最小缓冲的 4 倍 |

如果设备麦克风底噪大或回声严重，先调 `VAD_RMS_SPEECH`（连续对话的语音门限），
再考虑加 AEC（本机硬件已做，其他设备可能要软件补）。

### 5.3 音量

`VolumeCtl` 里假设 `STREAM_MUSIC` 的 max index 是 **15**（这台设备如此）。
其他设备常见 15 或 100，用 `AudioManager.getStreamMaxVolume(STREAM_MUSIC)` 读实际值即可，
代码里已做回读，只需确认显示换算没有写死 15。

有些定制 ROM 的音量是**按输出设备分开存**的（`volume_music_speaker` 等），
改档位时要确认改的是当前输出那条。

### 5.4 悬浮入口与自启

- `FloatEntryService`：`TYPE_APPLICATION_OVERLAY`（API 26+）/ `TYPE_PHONE`（更低）。
  首次需引导用户去「显示在其他应用上层」授权；某些 ROM 还要求「后台弹出界面」。
- `BootReceiver`：监听 `BOOT_COMPLETED`。部分 ROM（小米、华为、OPPO）需要用户手动把 App
  加入自启白名单，否则广播收不到。设置页里给出跳转入口更友好。

### 5.5 存储路径

默认读写 `/sdcard/Music/xiaozhi` 与 `getExternalFilesDir()`。
Android 10+ 的分区存储会限制前者，需要改用 MediaStore 或 `MANAGE_EXTERNAL_STORAGE`。
本项目 targetSdk 27，不受影响；**如果提高 targetSdk 要一并改这里**。

## 6. 在 Linux / macOS 上构建

脚本里几处 Windows 假设：

| 位置 | 现状 | 改法 |
|---|---|---|
| `AAPT2` / `AAPT` / `ALIGN` | 带 `.exe` | 去掉后缀 |
| `run_d8` | `-Djava.ext.dirs="$BT/lib"` | 该参数在 JDK 9+ 被移除，改用 `-cp "$BT/lib/d8.jar"` 直接调 |
| `aapt add` 路径分隔 | `/` | Linux 上正常，macOS 无需改 |

改完这三处即可，其余逻辑与平台无关。

## 7. 常见构建错误

| 报错 | 原因 | 处理 |
|---|---|---|
| `找不到 keytool` | JDK 不在 PATH | 设 `KEYTOOL=/path/to/keytool` 或 `JAVA_HOME` |
| `aapt2: error: failed to compile` | 资源里有不支持的属性 | 检查 `res/` 最近改动，注意 API 27 不支持新属性 |
| `AndroidManifest` 解析失败 | 注释里出现 `--` | aapt2 把 `--` 当注释结束符，注释里不能有连续两个减号 |
| `cannot find symbol: R.xxx` | 新增控件没写进布局或 id 拼错 | 先看 `build/gen/.../R.java` 里有没有 |
| 构建「成功」但 APK 没变 | `javac` 报错被 `tail` 吞掉 | **看 APK 时间戳或日志末尾的「完成:」，不要只看退出码** |
| `d8` 报 desugaring 警告 | 依赖里有 Java 8+ 接口 | 只是警告，可忽略（本项目已确认无运行时影响） |

构建日志在 Windows 下是 GBK 编码，`grep` 中文会失效：

```bash
iconv -f GBK -t UTF-8 build.log | grep -i error
```

## 8. 打包发布前自查

- [ ] `grep -rn "192\.168\." src/` 无真实内网地址
- [ ] `grep -rn "password\|secret\|token=" src/` 无明文凭据
- [ ] 没有 `debug.keystore`、`*.apk`、`build/` 被提交
- [ ] `AppConfig.java` 是被生成的那份，没有手改残留
- [ ] 版本号一致：`AndroidManifest.xml` 的 `versionName` 与 `OtaClient.APP_VERSION`
